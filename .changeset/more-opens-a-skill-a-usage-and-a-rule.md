`More` opens a skill, its usage and a rule as pages — and a rule finally says what it was offered.

The Skills stack has always answered *which one* in 420 pixels. Everything past that — the prose
against the flow it drew, seven versions against what each was applied, a statement against the
steps that cited it — is a table a column cannot hold without becoming a dashboard in a drawer. So
the Skills drawer and the Rules drawer each grow a `More`, drilled in, and it opens a **declared
board**: `skill`, `skill_usage` or `rule`, bound to one record, beside the stack rather than instead
of it. Three kinds join the registry; there are now thirteen.

All three are composed with `@invana/dashboard` from the reads the drawer already makes, so opening
one paints from cache. A dashboard is **data**: the page fetches, a composer turns the read into a
`DashboardSpec`, and the renderer draws it — and the `Dashboard ¦ spec.json` switch on each shows
the very document being rendered.

**A skill and its usage are two pages of one record.** `skill:abc` is what the playbook *declares*
and will engage — the trigger, the prose, the layer strip, what it composed, its bindings, its
versions. `skill_usage:abc` is what *happened* when it was offered. They split by tense, the same
pair the layer strip has always read two ways, and the usage board is addressed by the skill rather
than by a version because one read returns every version and its whole job is reading one count
against the next.

**Nothing computes a percentage the engine did not call readable.** A bucket below the floor draws
`—` under *too few to read*; a skill nothing has been offered draws `0 · 0 · —` under *no data
yet*. Both are `—` on purpose — neither is a statistic — and the caption is the only thing that
tells them apart, so it is never dropped for space. Versions are never summed: 2,786 offers across
seven texts is a number drawn nowhere, because *offered 1,204, applied 1,190* is a claim about one
text.

**A rule now says what it was offered.** `task_runs.rules_offered` has been written since the
statement migration and nothing had ever read it, so *never cited* could not be told from *never
offered* — the one distinction the evidence loop needs. `GET …/rules/{id}/citations` carries
`offered` beside `total`, and every published wording comes back with **its own** citation count,
counted by the engine rather than tallied from the bounded step list below it: a total taken from a
page is a different number wearing the same label.

The boards **read**. Publishing a version, binding an agent and deactivating a rule all stay where
the thing being changed is written, so a page anybody may open carries no act with a consequence to
read.
