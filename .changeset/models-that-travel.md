Models that travel, links that are declared, and a staged set you can see (docs/for-developers/modules/connect-and-model/spec.md).

**A model is a package now, not a row in a Graph.** `graph_models.package_id` is its portable identity and `graph_versions.content_hash` is the version's — taken over a canonical body with the name, description and semver left out, so the same shape exported from two Graphs hashes the same. That is what makes `upgrade` a real path rather than a re-import: `invana models export · import · upgrade · list · starters`, and the same three as routes (`…/models/{id}/export`, `POST …/models/import`, `POST …/models/{id}/upgrade`). A property type the target database cannot hold arrives as an **unpublishable draft naming the type** — never refused outright, never silently degraded. A name already in use comes back named, with both package ids, and is never merged.

**Two starters ship with the distribution — as ordinary artefacts.** `memory` (Observation · Insight · Evaluation) and `provenance` (Source · Record · Run) are files in exactly the format `models export` writes, land through exactly the import path any other artefact lands through, and arrive as drafts to be renamed. Nothing in the product reads their type names.

**Stitching is built.** `model_links` holds anchors and relationship links, both endpoints pointing at a **published** version — a draft cannot be stitched. An anchor names the property that resolves it and links without merging; a relationship link declares a cross-model edge type whose records arrive with a dataset. `POST …/model-links/preview` counts what an identity rule would actually resolve *before* the link exists, and a zero says the rule is wrong rather than returning quietly. `GET …/global-model` derives the union on read — anchored types counted once, with what each count came from — and stores nothing.

**The staged set is visible, discardable and committed in one action.** The draft *is* the staged set: `GET …/models/{id}/draft/staged` reads the difference between the draft and the version it replaces, `DELETE …/draft/staged/{change_id}` puts one element back, `POST …/draft/discard` puts them all back, and `POST …/models/{id}/commit` turns the whole set into the next published version and stamps its content hash. A staged delete names its dependents before the commit, not after.

**Studio: the Modeller is a panel, and Settings is two groups.** `?settings=model` is authoring now, not a read-only browser — the version bar, staged-first type lists each carrying a `staged` chip, the staged bar with discard-one and discard-all, `⌘↵` to commit, and Import (from a file or a starter). `?settings=links` is new: anchors, relationships, and the derived global model with what each count came from. The model canvas draws in the main area, and a selected type's form spans the column beneath it rather than opening a modal over the drawing. The separate Connection rail icon is gone: the connection is a **field group inside the settings form**, with `Test connection` and `Introspect` beside the fields and capabilities folded in — `?settings=connection` still resolves, onto that group.

**The model canvas is reachable, and it edits.** The main area had no branch for `kind = model`, so the canvas — and with it the type form, the add gestures and the delete — never rendered at all. It has its own header now (model · version · close), `Edit` and `Delete type` are wired to the same forms the create gestures use, and a delete is confirmed as **staging** a delete rather than as deleting. The panel gained what `domain-models.md` puts there: an `add` on both the node-types and edge-types sections, a Keys section, and the selected type's properties with add and remove while drafting. `GET …/models/{id}/versions/{id}/diff` gives the version bar the "what changed between them" it had been promising. The compatibility banner, orphaned when `/modeller` retired, now sits on the model panel — the surface whose saves the server would otherwise refuse.

**Authoring no longer hides behind a draft.** Every add — node type, edge type, property key — and every property edit was gated on an open draft, and a published model has none: the whole editor rendered with no buttons at all, which reads as *not built* rather than as *read-only*. The affordances are always offered now and the first one used opens the draft on the way; a published version states that it is published, where the editing would have been, with the one action that changes it. The canvas's type form regains the `Create draft to edit` affordance it always had but was never given anywhere to go.

**Clicking a type on the model canvas selected nothing.** `ClickSelectBehaviour` and `ClickInspectBehaviour` both claimed `pointer+click`, so the canvas refused the second — and the refused one is what feeds `onSelect`. The click was dropped before it reached any of this. `click-select` stays registered for the panel → canvas highlight the `SelectionBridge` drives programmatically, but no longer claims the gesture — on **both** the authoring and the read-only path, since a published model renders the second one. Multi-select stays available through brush and lasso.

**The model canvas threw on mount.** `SchemaCanvas`'s authoring path reads the active tool through `useTool`, which needs a `GraphToolProvider` above it — the retired Modeller page lifted one over its whole shell, and the new canvas had none, so it crashed into the error boundary before rendering anything. The provider now wraps the canvas **and its header**, because the `Select · Add · Connect · Delete` switcher lives there and is the gesture's only entry point: a switcher outside the provider cannot arm Add or Connect.
