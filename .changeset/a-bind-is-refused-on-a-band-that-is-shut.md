The lens half of a bind runs: a skill whose plan reaches a band the agent's guardrails have shut is refused when someone binds it (BN10).

A plan node declares a **band** — graph data, llm, third party, cache, human — and never a
participant: which model a run reads, or which person it asks, is decided inside the run. So the
check asks the only question a bind can honestly answer about a band: *is it shut to everything?*
Three readings say yes — a `<layer>/** deny`, a closed band that names nothing inside it, and a
Graph whose every participant in that band is denied. One permitted participant and the bind
stands; a run that then picks a denied one says *cannot answer — outside the lens*, which widening
recovers.

It reads **guardrails**, never worlds — including the world an agent carries by default. A
guardrail is always in force; a world is picked per question and may only narrow inside one, so a
world that shuts a band is the run-time narrowing a bind deliberately does not refuse on.

The refusal names the band, the rule that denied it and one participant it actually checked, beside
the step and bound the envelope half names. `checked` now reads `envelope · lens` with nothing left
in `not_checked`.

**Studio's Bindings tab gains its third section.** `GET …/skills/{id}/agents` runs both checks as a
dry run per agent, so **bound · refused · not bound** is one read and the refusal is visible before
the click rather than one click at a time. The card draws whichever half refused.

The band a plan node declares is now the governed layer itself rather than a second spelling of it,
so the Flow tab's strip and the lens can no longer disagree about what a step touches.
