## Findings

| Severity | Where | What | How to fix |
|---|---|---|---|
| should-fix | `engine/src/invana/cli/commands/models.py` `_publish` | The CLI calls `PublishReviewManager.advance_due` for the whole install, not just its own review. It then runs inline every migration run that step opens. So `invana models publish` on one model can apply another model's approved review, on any Graph, from the caller's terminal. | Scope the step to the review: `advance_due(…, review_id=)`, or run inline only the ids whose review is the one just opened. |
| should-fix | `apps/modeller/querysets/publish_review.py` `open_for_model` · migration 073 | The one-open-review rule is a check followed by an insert, with no lock and no constraint behind it. Two concurrent `POST …/publish` calls can both open a review. | Add a partial unique index on `model_id WHERE status IN ('previewing','pending','migrating')`, or lock the model row before the check. |
| should-fix | `activity/managers/publish_reviews.py` `_approvers` · `publish` (422s) | The 422 refusals are plain sentences: *no other owner*, *approver not an owner*, *version override*. They carry no `error` code and no structured owner list. B11's 403 and this session's own 409s (`breaking_publish_needs_review`, `review_open`) do carry them. C04 has to parse text to show "names the rule and the owners". | Return `{error: "approver_required" \| "approver_not_owner" \| "version_override_refused", owners: [...], message}`. |
| should-fix | `cli/commands/models.py` `_change_lines` | Each line prints only `breaking`/`additive` and the reason, e.g. "breaking  removed property". It does not say which type or property, so neither the dry run nor the review output can be acted on. | Print `target_kind`, `type` and `property` alongside the reason. |
| should-fix | `docs/products/modeller.md` › Decisions *Publish review* | The product doc still lists "loosened guardrail" as breaking. The feature file's Not building table explicitly excludes it. | should-fix | Gates not run | `MigrationScan` has never run against a graph database.
