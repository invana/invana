## Findings

| Severity | Where | What | How to fix |
|---|---|---|---|
| should-fix | `runtime/managers/mcp.py` `add` · `refresh` · `_check` · `_list` | Every refusal is a plain sentence with no `error` code. Two different 409s (name taken, extra missing) share one status. Four different 422s (bad name, non-http URL, unreachable, unauthorised) share another. C03's *Add MCP server* form can only tell them apart by parsing the text. B10's review raised the same gap. | Return structured details, e.g. `{error: "mcp_name_taken" \| "mcp_extra_missing" \| "mcp_bad_name" \| "mcp_bad_url" \| "mcp_unreachable" \| "mcp_unauthorized", url?, env?, message}`. List the codes in the feature file's Endpoint table. |
| should-fix | `plugins/mcp/plugin.py` `_declaration` · `summary` | A tool's version is keyed on `description`, `input_schema` and `annotations` only. `summary` prefers `title`. So if a refresh changes only the title, the manifest's `summary` changes while `key@version` stays the same. Two different manifests then carry one version, which breaks the rule that a version names one declaration. | Add `title` to `_declaration`, or derive `summary` only from fields that are versioned. Update MC3 to match. |
| should-fix | Gates not run (the log says so) | No test has run an MCP step through the interpreter. Untested paths: the `send` hold on a non-read-only MCP tool, the `plugin_disabled` refusal for `kind = mcp`, and procrastinate routing via `tool_manifest`. These are the safety-relevant paths (C6, C8). The code reuses the tool path, but the `SWITCHABLE` widening is the change that makes them work, and nothing asserts it. Migration 076 has not been applied to the dev Postgres. Until it is, every `invana plugins …` read fails, because each one loads MCP first. | Add one positive and one negative test: a disabled `mcp.*.book` is refused with `plugin_disabled`, and an enabled one holds on an approval (`needs_input`). Run `invana migrate` in the dev container before C03. |
| note | `plugins/mcp/client.py` `call_tool` | Tool output (`content`, `text`, `structured`) has no size limit before it becomes the step output and its stored row. A chatty server can bloat `task_runs`. | Cap or truncate `content` and `text` the same way other network tool outputs are capped, and record that the output was truncated. |
| note | Package name in copy | The feature file's 409 text and `_check` say `pip install 'invana-engine[mcp]'`, which matches `pyproject` `name = "invana-engine"`. Feature C10, the changeset and the existing tool-plugin 409 all say `invana[mcp]` / `invana[...]`. | Pick one install name across the feature file, the changeset and both managers. |
| note | `runtime/managers/plugins.py` `set_enabled` | An Admin can enable a stored MCP server that is not loaded even when the `mcp` extra is missing. The extra-missing *tool* plugin is refused with 409. The feature file's seam covers only *not yet restarted*. | Decide in the feature file whether *extra missing* also refuses enabling. If it should, refuse with the same 409 the tool plugin returns. |
| note | `runtime/managers/mcp.py` `add` (URL) | The only check on the Admin-supplied URL is http(s). Loopback and private hosts are allowed, which self-hosted servers need, and redirects are followed. httpx drops `Authorization` on cross-origin redirects, so the token does not leak. This is acceptable for an install-Admin-only act. | Record the decision in Decisions so a later SSRF pass does not reopen it. |
| note | `plugins/__init__.py` `install_mcp` | Process-global MCP state. Tests that load MCP must reset with `install_mcp(()); catalogue.sync()`, or the set leaks into other tests. The log records this, and the test's `clean_registry` fixture does it. | Consider moving `clean_registry` into `tests/plugins/conftest.py` so later tests inherit it. |
