# Spec site

A browsable site over `specs/`, with mermaid, the spec hierarchy and a live `@invana/canvas` graph of every dependency, loop and gap. It is for Ravi and the team to practise graph-thinking on Invana's own decisions.

| | |
|---|---|
| Goal | Every spec in `specs/` reads as a page with its mermaid diagrams and its Depends on / Used by / Gaps. One canvas graph, parsed from the `.md` files, shows the hierarchy, linear and non-linear dependencies, loops and gaps, and uses every canvas feature that has a real job here |
| Specs | — (team tooling, like `scripts/specs/check.py`; no product story) |
| Not in this project | Filling any placeholder (that is the later cleanup and the system-design migration) · edits in the canvas or design-kit repos (gaps go to `recommend`) · publishing the site publicly · loading the graph into an Invana Graph · `graph-layer-maplibre` (specs have no geography) |

Run it: `python3 .claude/skills/run-project/run.py spec-site` (the project-lead does, with `--start`).

## Rules for every session

| Rule | Detail |
|---|---|
| `.md` is the source, JSON is a parse | The `specs/**/*.md` files are written for humans and are the only source of truth. `specs-graph.json` is generated by `check.py --graph` and never edited or committed by hand. To change the graph, change the `.md` |
| No invented edges | Every node and edge comes from frontmatter or structure the parser can read (tables, sections, IDs). A missing fact becomes a placeholder, never a guessed edge |
| Placeholders say so | A placeholder file carries `status: placeholder`; a placeholder section's body starts `> Placeholder —`. Nothing else in a placeholder decides anything |
| The parser owns the analysis | Cycles (SCC), blocking chains, orphans and gaps are computed in Python into `analysis` in the JSON. The graph app renders flags and never recomputes them |
| Canvas owns canvas logic | The graph app configures released `@invana/canvas*` packages and composes `@invana/design-kit`, tokens only. A missing canvas or kit feature is a `recommend` row for the canvas repo, not code in the site |
| Pinned versions | Committed manifests pin published `@invana/*` versions (canvas `0.0.17`). A local `link:` is for local iteration only and never lands |
| Where it lives | Parser in `scripts/specs/`; the site in `scripts/specs/site/` (MkDocs config, hooks, generated pages); the graph app in `scripts/specs/site/graph/`. Build output is gitignored |
| Few tests | A few positive and negative tests per phase, no mocks of the spec tree; tests use fixture spec folders |
