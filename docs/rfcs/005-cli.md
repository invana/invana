# RFC-005: Invana CLI

> **Status**: Implemented
> **Author**: Ravi Merugu
> **Created**: 2026-04-09
> **Updated**: 2026-04-10
> **Depends on**: RFC-001 (Graph Connectors), RFC-004 (Graph Data Loaders)

## Summary

A `cli` module inside the engine that exposes the `invana` command-line tool. The CLI provides sub-commands for common operational tasks — starting the server, running migrations, loading datasets, and checking the version — without requiring users to know module paths or write Python scripts. Connection details are resolved from environment variables, `.env` files, or explicit CLI flags, following the same priority chain as the rest of the engine.

## Motivation

- **No entry point today.** CLAUDE.md lists `invana start`, `invana migrate`, `invana version` as the CLI contract, but nothing implements them. Users must run `uvicorn invana.server.app:app` directly, which is not intuitive for non-Python users.
- **Dataset loading has no user-facing entry point.** RFC-004 implemented `CSVLoader` but it is only accessible via Python code. A CLI command makes it usable in CI pipelines, container init scripts, and documentation examples.
- **Connector selection is explicit.** Users supply a dotted-path connector class via `--connector`. The two built-in connectors (`invana.graph.connectors.OpenCypherConnector` and `invana.graph.connectors.GremlinConnector`) cover Cypher and Gremlin databases respectively. Integration packages provide specialised subclasses (e.g. `invana_neo4j.Neo4jConnector`).
- **If we don't do this.** Every tutorial, Dockerfile, and CI script invokes the engine differently, making onboarding harder and documentation harder to maintain.

```
engine/src/invana/cli/
```

### Directory Structure

```
engine/src/invana/
├── cli/

    ├── __init__.py
    └── test_cli.py        # unit tests for CLI commands and import utilities
```

### Entry Point Registration

`pyproject.toml`:

```toml
[project.scripts]
invana = "invana.cli.main:app"
```

After `pip install invana-engine` (or `uv sync`), the `invana` binary is available on `PATH`.

### CLI Commands

#### `invana version`

```
$ invana version
Invana 0.0.0
```

Reads `settings.app_version`. No flags.

---

#### `invana start`

```
$ invana start [--host HOST] [--port PORT] [--reload]
```

Boots the FastAPI server via `uvicorn`. Equivalent to:

```bash
uvicorn invana.server.app:app --host 0.0.0.0 --port 8000
```

| Flag | Default | Env var | Description |
|---|---|---|---|
| `--host` | `INVANA_HOST` → `127.0.0.1` | `INVANA_HOST` | Bind address |
| `--port` | `INVANA_PORT` → `8000` | `INVANA_PORT` | Listen port |
| `--reload` | `False` | — | Enable uvicorn auto-reload (dev only) |

---

#### `invana migrate`

```
$ invana migrate [--database-url URL]
```

Runs Alembic migrations to head. Wraps `db.run_migrations()`.

| Flag | Default | Env var | Description |
|---|---|---|---|
| `--database-url` | `INVANA_DATABASE_URL` | `INVANA_DATABASE_URL` | App-state DB connection string |

---

#### `invana loader`

```
$ invana loader <path> [options]
```

Loads all CSV files from `<path>` into a graph database using `CSVLoader`.

**Positional:**

| Argument | Description |
|---|---|
| `path` | Dataset root directory. Must contain `nodes/` and/or `relationships/` subdirectories. |

**Connection flags:**

| Flag | Default | Env var | Description |
|---|---|---|---|
| `--uri` | `INVANA_GRAPH_URI` | `INVANA_GRAPH_URI` | Graph DB connection URI. Required (CLI or env). |
| `--username` | `INVANA_GRAPH_USERNAME` | `INVANA_GRAPH_USERNAME` | DB username (optional, some DBs embed in URI). |
| `--password` | `INVANA_GRAPH_PASSWORD` | `INVANA_GRAPH_PASSWORD` | DB password. Prompted interactively if URI requires auth and flag is absent. |
| `--connector` | `INVANA_GRAPH_CONNECTOR` | `INVANA_GRAPH_CONNECTOR` | **Required.** Dotted path to connector class, e.g. `invana.graph.connectors.OpenCypherConnector`. |

**Loader flags:**

| Flag | Default | Description |
|---|---|---|
| `--batch-size` | `500` | Records per bulk call. |
| `--skip-on-error` | `False` | Log and skip failures instead of aborting. |
| `--dry-run` | `False` | Parse and validate only — no DB writes. |
| `--no-source-ids` | `False` | Omit `_csv_source_id` property from loaded records (`keep_source_ids=False`). |

**Usage examples:**

```bash
# OpenCypher / Neo4j, Memgraph
invana loader datasets/air-routes \
  --uri bolt://localhost:7687 \
  --connector invana.graph.connectors.OpenCypherConnector \
  --username neo4j --password secret

# Neo4j-specific connector (invana-neo4j package)
invana loader datasets/movies \
  --uri bolt://localhost:7687 \
  --connector invana_neo4j.Neo4jConnector \
  --username neo4j --password secret

# Gremlin
invana loader datasets/air-routes \
  --uri ws://localhost:8182/gremlin \
  --connector invana.graph.connectors.GremlinConnector

# Tune loader
invana loader datasets/movies \
  --uri bolt://localhost:7687 \
  --connector invana.graph.connectors.OpenCypherConnector \
  --batch-size 1000 \
  --skip-on-error \
  --dry-run

# Connection from environment variables
INVANA_GRAPH_URI=bolt://localhost:7687 \
INVANA_GRAPH_CONNECTOR=invana.graph.connectors.OpenCypherConnector \
INVANA_GRAPH_USERNAME=neo4j \
INVANA_GRAPH_PASSWORD=secret \
invana loader datasets/air-routes
```

### Connector Resolution

Both `--uri` and `--connector` are required flags. The `--connector` value must be a fully-qualified dotted import path to a connector class. Resolution is handled by `import_class_from_dotted_path` in `engine/src/invana/utils.py`:

```python
def import_class_from_dotted_path(dotted: str) -> type:
    module_path, cls_name = dotted.rsplit(".", 1)
    module = importlib.import_module(module_path)
    return getattr(module, cls_name)
```

Available built-in connectors (short paths re-exported from `invana.graph.connectors`):

| Connector | Databases | Dotted path |
|---|---|---|
| `OpenCypherConnector` | Neo4j, Memgraph, ArcadeDB | `invana.graph.connectors.OpenCypherConnector` |
| `GremlinConnector` | JanusGraph, Amazon Neptune, TinkerGraph | `invana.graph.connectors.GremlinConnector` |

Integration packages extend these base connectors (e.g. `invana_neo4j.Neo4jConnector`). Any installed class can be specified via `--connector` — no registry, no auto-detection.

### Settings Extension

Add to `engine/src/invana/settings.py`:

```python
# Graph connector (used by CLI loader and future API routes)
graph_uri: str = ""                  # INVANA_GRAPH_URI
graph_username: str = ""             # INVANA_GRAPH_USERNAME
graph_password: str = ""             # INVANA_GRAPH_PASSWORD
graph_connector: str = ""            # INVANA_GRAPH_CONNECTOR (dotted path, optional)
```

CLI flag values override settings values — the loader command reads settings as defaults and the explicit flag (if given) wins.

### Error Handling & UX

- **Missing URI or connector:** Click raises a `UsageError`; exits with `Error: Missing option '--uri'.` or `Error: Missing option '--connector'.`
- **Import error on `--connector`:** Exit with: `Error: Cannot import connector "invana_neo4j.Neo4jConnector". Is the package installed?`
- **Connection failure:** The connector raises `ConnectionError`; the CLI catches it and exits with a human-readable message.
- **Load summary:** After a successful load print a progress table:

```
Dataset: datasets/movies
  ✓ Person     3 vertices
  ✓ Movie      9 vertices
  ✓ ACTED_IN  13 edges
  ✓ DIRECTED   9 edges

Total: 12 vertices, 22 edges in 0.84s
```

- `--dry-run` prefixes the output line with `DRY RUN —`.

### Framework Choice: Click (not Typer)

Click is already a transitive dependency (via FastAPI → Starlette). Typer is a thin wrapper over Click and would add a dependency for no functional gain. Using Click directly keeps the dependency footprint minimal.

`asyncio.run()` is used to bridge Click's synchronous callback into the async `CSVLoader` and connector lifecycle.

## Alternatives Considered

| Alternative | Pros | Cons | Why rejected |
|---|---|---|---|
| Typer | `@app.command()` decorator, auto-generates `--help`, type inference | Extra dependency on top of already-present Click | Click is sufficient and already available |
| argparse (stdlib) | Zero deps | Verbose, no `--help` auto-generation as clean as Click | Click is already present, no reason to drop down |
| Connector registry (`--connector neo4j`) | More ergonomic short names | Registry must be maintained in lockstep with published packages | Explicit dotted path is self-documenting and requires no registry maintenance |
| `INVANA_CONNECTOR` env var with short names | Friendly for Docker | Same registry maintenance problem | Dotted-path env var `INVANA_GRAPH_CONNECTOR` is equally Docker-friendly |

## Security Considerations

- **Password in flags:** `--password` is a Click option, not an argument, so it doesn't appear in `ps aux` as a positional. Recommended usage is via env var (`INVANA_GRAPH_PASSWORD`) or a `.env` file with restricted permissions.
- **Dotted-path import:** `--connector` calls `importlib.import_module()` on user-supplied input. The CLI validates the string format (`module.ClassName`) before importing and catches all `ImportError`/`AttributeError` exceptions, ensuring no arbitrary code paths are opened beyond installed packages.
- **Path traversal in `loader <path>`:** `CSVLoader` already resolves and validates the path (RFC-004). The CLI does no additional path handling.

## Performance Considerations

- The CLI is a thin orchestration layer. All performance-sensitive work happens inside `CSVLoader` and the connector. No additional overhead is introduced.
- For very large datasets, `--batch-size` should be tuned at the CLI level rather than requiring code changes.

## Testing Strategy

- **Unit tests** (`engine/tests/cli/test_cli.py`): `import_class_from_dotted_path` (valid path, invalid module, invalid class), version command output, help command, loader missing-flag errors. No DB or network required.
- **CLI integration via `click.testing.CliRunner`**: invoke `invana loader`, `invana version`, `invana start --help` and assert exit codes and output text.
- **Coverage target**: ≥ 80%.
