# Layer 2 — Graph (container + settings)

> **Status**: S1.5 + S2 shipped · S3 partial (schema wired; canvas stubbed) · **Tracked by** [RFC-017](../../rfcs/017-graph-as-primary-container.md)
> **Author**: Invana Team
> **Created**: 2026-05-21

> **About this doc.** Layer 2 collapses the original Workspace + Mission split into a single `Graph` container (per RFC-017). Membership and invitations come from Layer 1; everything else — DB binding (1:1 `GraphConnection`), intent/objectives, setup wizard, settings landing — lives here. This doc records the shipped surface; § 2.4–2.7 (Skills, Instructions, LLM, Agents) are scaffolded in `mvp.md` and ship in later slices.

---

## Summary

`Graph` is the primary container. It carries `name`, `slug` (unique per owner), `intent`, `description`, `objectives`, `success_criteria`, `status` (`active` | `archived`), `setup_state` (JSONB), and `created_by_id`. Each `Graph` has a 1:1 `GraphConnection` child carrying the DB binding (`connector_class` dotted path, `uri`, Fernet-encrypted `auth`, `read_only`, runtime `status`/`schema_id`/`latency_ms`).

All graph-scoped routes live under `/api/v1/u/{username}/{graphSlug}/...`. The path parameter is named `graphSlug` in routing code; the underlying data field is still `Graph.slug`.

A new Graph progresses through a 4-section **setup wizard** (Graph Info / Intent / Skills / Datasets). The first two are required; Skills and Datasets are skippable. Modeller / Explorer / Query are gated by `require_graph_setup_complete` until both required sections are done.

## Shipped surface

### 2.1 Graph CRUD

**Engine**
- `POST /api/v1/graphs` — body: `{name, slug, intent?}` · any authenticated user · creator becomes `admin` member.
- `GET /api/v1/graphs` — lists Graphs the caller is a member of.
- `GET /api/v1/u/{username}/{graphSlug}` — graph detail (member-only).
- `PATCH /api/v1/u/{username}/{graphSlug}` — admin-only · partial update of `name`, `description`, `intent`, `objectives`, `success_criteria`, `status` · saving non-empty `intent` auto-completes the `intent` wizard section.
- `DELETE /api/v1/u/{username}/{graphSlug}` — admin-only · hard delete, cascades downward per RFC-012 matrix · sole-admin self-removal → 409.

**Studio**
- `/graphs` — list with status badges + delete confirm.
- `/graphs/new` — create page (`name` → autogenerated `slug` → optional `intent`).
- `/u/:username/:graphSlug` — graph overview page (wizard progress + quick actions).

### 2.2 Setup wizard + feature gating

**Engine**
- `setup_state: JSONB` on `graphs` — keys `graph_info`, `intent`, `skills`, `datasets`, each `{completed_at?, skipped_at?}`.
- `POST /u/{username}/{graphSlug}/setup/{section}` body `{action: "complete" | "skip" | "reset"}` — required sections (`graph_info`, `intent`) cannot be skipped.
- `require_graph_setup_complete` dep — gates `/query`, `/schema/active-version`, `/connection/introspect`. Computes from required-section completion in `setup_state`.
- Auto-completion: `graph_info` completes on every successful `PUT /connection` (so a prior reset is undone by saving again); `intent` completes when `PATCH` saves a non-empty `intent`.

**Studio**
- Overview page renders a wizard card with one row per section: status icon (done / skipped / todo), Set up / Edit button, Skip (optional sections only), Reset (done / skipped sections).
- Modeller / Explorer / Query buttons on the overview disabled until required sections complete.
- After saving in Connection settings or Intent settings, user is navigated back to the overview.

### 2.3 GraphConnection (1:1 child)

**Engine** — `/api/v1/u/{username}/{graphSlug}/connection`:
- `GET` — returns `GraphConnectionRead | null` (member).
- `PUT` — admin-only · full-replace body (`GraphConnectionCreate`) · `connector_class` is **immutable** after first save (409 on change) · empty `auth: {}` on edit preserves stored credentials (server treats falsy auth as no-op) · marks `graph_info` complete · registers / reconnects via `GraphConnectionManager`.
- `DELETE` — admin-only · hard delete · deregisters from manager · resets `graph_info` wizard section.
- `POST /connection/test` — admin-only · builds a transient connector with the supplied creds, attempts connect, returns `{ok, latency_ms?, error?}`, discards. Used to gate the Studio Save button.
- `POST /connection/ping` — member · forces a reconnect via the manager (202).
- `POST /connection/introspect` — admin-only · re-runs schema introspection against the live DB (202).

**Studio**
- `/u/:username/:graphSlug/settings/connection` — `GraphForm`. Test Connection gates Save (Save disabled until Test succeeds). Always sends `GraphConnectionCreate` on PUT (full-replace semantics); on edit, the connector input is locked (immutable) and an empty `auth: {}` is sent when credentials are not re-entered.

### 2.8 Graph settings shell

**Studio**
- `/u/:username/:graphSlug/settings` — landing index. Lists sub-settings as links: Connection · Intent · Skills (S5 placeholder) · Datasets (S6 placeholder) · Members · Invitations.
- Admin-only sections are filtered out for non-admins via `rolesForGraph(username, graphSlug)`.
- Left rail (`App.tsx`) shows a graph-scoped **Graph settings** entry only while inside a Graph; off-graph, only Profile.
- Bottom rail still has Profile (`/settings/profile`).
- Members + Invitations pages (`/settings/members`, `/settings/invitations`) come from Layer 1.

### 2.x Studio Explorer / Modeller (Layer 4.1 / Layer 5.5)

Mounted under `/u/:username/:graphSlug/{modeller,explorer}` and consume Layer 2 endpoints via the graph-scoped query and schema routes. Canvas rendering is stubbed — see Risk notes in `mvp.md`.

## Removed legacy surface

S2 deleted the back-compat shims that existed in earlier slices:

- `engine/src/invana/server/routes/graphs.py` — `/api/v1/graph-connections/*` (CRUD + reconnect + introspect + project).
- `engine/src/invana/server/routes/legacy_query.py` — `/api/v1/graphs/{connection_id}/query`.
- `engine/src/invana/server/routes/legacy_schemas.py` — `/api/v1/schemas/{schema_id}/active-version`.
- Studio: `graphConnectionsApi.*` and the six `useLegacy*` hooks.
- Types: `GraphConnectionUpdate`, `GraphConnectionListResponse`, `GraphStatus` alias.

All callers moved to graph-scoped routes. The studio's connection PUT (full-replace) replaces the partial PATCH the legacy surface offered.

## Wire format notes

### `GraphConnectionCreate` (PUT body)

```
name              string  required, 1–255
description       string  default ""
uri               string  required, 1–2048
connector_class   string  required, 1–512 (immutable after first save)
auth              object  default {}  — {} on edit means "keep existing creds"
read_only         bool    default false
```

### `QueryResponse` (POST /query)

```
result_type         "graph" | "tabular"
query_language      "cypher" | "gremlin"
data                GraphResponse | null   — populated when result_type=graph
rows                list[dict] | null      — populated when result_type=tabular
execution_time_ms   int    — from metadata.duration_ms, rounded
row_count           int    — nodes+edges for graph; len(records) for tabular
```

Detection: any nodes or edges present ⇒ `graph`; otherwise ⇒ `tabular`.

## Notable design choices

- **PUT semantics on `/connection`.** Full-replace, not partial update. The client always sends `GraphConnectionCreate`. This lets a single endpoint handle both "first save" and "edit" without a separate POST / PATCH split; the server's `put_graph_connection` service branches on `existing is None`.
- **Immutable `connector_class`.** Changing the connector after schema introspection invalidates the seeded schema. Enforced server-side (409). On the form, the Connector select is rendered as a disabled Input on edit, with the existing value shown.
- **Empty `auth` preserves credentials.** Removes the need for a separate "leave-blank-to-keep" sentinel. Server: `if payload.auth:` only re-encrypts when a non-empty dict is sent.
- **Wizard section auto-completion.** `graph_info` completes on every save (not just first) so resetting + re-saving leaves the section complete. `intent` completes whenever a non-empty intent lands via PATCH.
- **`graphSlug` in routing code.** The URL path parameter is named `graphSlug` (not `slug`) in router paths, `useParams` types, API client + hook arg names, and mutation arg keys. The data field on the Graph entity stays `slug`. This disambiguates the URL-param meaning from the generic concept of "a slug" elsewhere in the codebase.

## Open items (not blocking)

- **Canvas integration.** Modeller's `SchemaCanvas`, Explorer's `GraphCanvas`, and `CanvasToolbar` are placeholders. The old `@invana/canvas-core` + `@invana/layouts-d3-force` packages are unpublished; the sibling `@invana/canvas` exposes a redesigned API surface that the old plugin code can't be retargeted to mechanically. Tracked in `mvp.md` Risk notes.
- **`graph_connections.graph_id` is nullable.** Historical artefact from the deleted standalone connection surface. Tighten to `NOT NULL` once any orphan rows are cleared.
- **Project endpoint.** The legacy `POST /api/v1/graph-connections/{id}/project` was deleted as a no-op (it only returned a status placeholder). Real schema projection (creating indexes/constraints on the live DB) lands when needed by the Modeller's Apply Schema flow.
